Same idea, two spellings

JavaScript

let userName = "Alex";
console.log(userName);

Python

user_name = "Alex"
print(user_name)

Both print Alex. Learn the idea once, then learn two spellings.

Ask chat: "Spot 3 differences." Expect: let, camelCase vs snake_case, the semicolon, console.log vs print.

"Engineers pick the language for the job. Today we learn the ideas both share."

Why learn both?

JavaScript

  • Runs in every browser: clicks change the page
  • React, Vue, Angular build big UIs
  • Node.js runs it on servers too
  • Hard parts: async, events, tools that change fast

Python

  • Reads like English: logic over syntax
  • Data (pandas), AI (PyTorch), back ends (Django, Flask)
  • Fewer lines for the same idea
  • Hard parts: indentation rules, dynamic types, speed

They often run in the same system: JS in the browser, Python behind it.

  • JS started in the mid-1990s to make pages interactive. Python started in the late 1980s / early 1990s with "readability first".
  • "The hard parts are normal. Learning to reason about them is part of the job."
diagrams/JP1-01-runtimes.tldr

"Both are interpreted: the runtime reads your file and runs it line by line, at run time. That's why you can change a line and run again in a second."

  • Common ground: variables, conditions, loops, functions, data structures.
  • Difference: JS is event-driven (waits for clicks); Python usually runs top to bottom.

diagrams/JP1-03-index-vs-key.tldr

"Complex types hold many values."

  • List / array: in order, counted from 0. Reading one slot by its index is instant.
  • Object / dict: key → value. You reach a value only through its key.

  • Lists hold any mix of types. Node prints strings in single quotes: that's just how it displays them.
  • Dot notation is JS-only (user.name). Python uses user.get("name") or user["name"].
  • Bracket notation works in both: add with user["city"] = …; remove with delete (JS) / del (Python).

If asked: user.get("phone") → None; user["phone"] → KeyError. JS user.phone → undefined.

Can it change? mutable.js · mutable.py

** CODE ALONG, about 3 minutes. ** Students: mutable.js and mutable.py.

TYPE THIS, in order

mutable.js · part 1

// a list is mutable: it changes in place
let colors = ["red", "green"];
colors.push("blue");
console.log(colors);

mutable.py · part 1

# a list is mutable: it changes in place

mutable.js · part 2 (add below, after a blank line)

// a string is immutable: you get a NEW string
let name = "alex";
let loud = name.toUpperCase();

mutable.py · part 2 (add below, after a blank line)

# a string is immutable: you get a NEW string
name = "alex"
loud = name.upper()
print(name, loud)

mutable.js · part 3 (add below, after a blank line)

// the bug: two labels, one list
let copy = colors;
copy.push("pink");
console.log(colors);

mutable.py · part 3 (add below, after a blank line)

# the bug: two labels, one list
copy = colors
copy.append("pink")
print(colors)

diagrams/JP1-04-mutable.tldr

"Mutable is like a mutant, like Wolverine: it can change. Immutable never changes; you get a new one."

  • Mutable: lists / arrays, dicts / objects, sets.
  • Immutable: strings, numbers, booleans.
  • Why care: shared state. One part of a program changes a list another part is still using.
